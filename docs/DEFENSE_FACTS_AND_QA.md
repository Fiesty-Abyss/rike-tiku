# 答辩事实与问答

## PR #33 补充口径

- 为什么 AI 不直接改变答案？正式判分与 `STANDARD` 是数据库事实；AI 只解释或生成 `PENDING` 候选，人工审核是发布门禁。
- “深度思考”是否展示思维链？不展示、不持久化、不写日志；服务端只保存最终 `content`。
- 联网搜索如何防提示注入？只调用官方结构化搜索接口，限制结果数、超时和 URL；摘要标记为 `UNTRUSTED_WEB_CONTEXT`，不能覆盖 STANDARD。
- 变式题为何不是聊天文本？独立结构化 API 复用候选 Parser、答案校验和确定性判分，避免出现只有题干没有选项的不可作答结果。
- PDF 如何实现？页面提供 A4 print CSS 和 `window.print()`；PDF 由系统打印对话框“另存为 PDF”，不引入重型 PDF 依赖。

## 1. 为什么用 DeepSeek？

项目需要中文物化生文本推理、结构化 JSON 和 OpenAI-compatible HTTP 契约。DeepSeek 作为文本“大脑”统一承担错因、当前题答疑和候选生成，减少多模型业务分叉；本科 Demo 默认用成本和延迟更适合的 `deepseek-v4-flash`。

## 2. 为什么需要 GLM？

部分物理、化学、生物题依赖装置图、受力图、电路图和实验图。文本模型无法可靠读取图片，因此用 `glm-4.6v-flash` 提取受控视觉语义。

## 3. 为什么不直接让 GLM 解题？

项目把 GLM 定位为“眼睛”，输出 `UNTRUSTED_VISION_CONTEXT`；DeepSeek 才做统一文本推理。这样职责清楚，视觉失败也不会直接改变答案或判分。

## 4. 为什么 STANDARD 是权威？

STANDARD 来自题库正式审核事实，参与正式结果解释；模型输出存在不确定性，只能作为个性化辅助。系统始终遵循 `STANDARD > AI`。

## 5. 怎么防止 AI 改答案？

正确答案与 STANDARD 来自冻结练习题，AI 表只保存辅助分析或候选内容。Prompt 明确数据边界，Parser 严格校验，业务代码不提供修改 STANDARD 的写路径，测试还比较调用前后 hash。

## 6. 怎么避免学生询问身份时暴露 Provider？

代码级 identity guard 在调用模型前拦截“你是谁、什么模型、什么 API”等问题，固定返回 RIKE 理科学习助手身份；模型输出还会做 Provider disclosure 过滤。

## 7. 为什么只允许 10 轮？

会话只服务当前题。10 轮、500 字单条、最近 12 条和 6000 字预算可以控制成本、延迟和上下文漂移，也便于本科项目复现。

## 8. 为什么一批最多 3 道？

候选必须人工审核。小批量可降低一次失败的影响、控制成本，并避免审核积压；同母题 PENDING 还限制为 6 道。

## 9. 怎么防重复？

request hash 防止相同有效请求重复执行；`nei_rong_ha_xi` 拒绝完全相同内容；批内 hash 去重；trigram/Jaccard 0.72 只标记疑似重复供人工判断，不引入向量数据库。

## 10. 为什么 AI 题必须人工审核？

模型生成的答案和解析在审核前都只是 CANDIDATE。只有教师或管理员评价学科正确性、答案正确性、可解性、知识一致性和难度匹配并 APPROVED 后才能发布。

## 11. AI 宕机怎么办？

Provider 有连接/请求超时、最多一次临时失败重试和受控错误。AI 失败不影响登录、练习、判分、错题或 STANDARD；图片必要的候选生成直接 FAILED，不让文本模型猜图。

## 12. 为什么没有 RAG 或向量数据库？

当前问题依赖冻结题目、正确答案、STANDARD 和知识点等受控事实，不需要外部知识检索。引入 RAG 会扩大数据、评估和运维范围，不符合本科项目最小可解释边界。

## 13. Key 怎么管理？

环境变量可作为回退；本地毕设 Demo 允许管理员把 Key 保存到本机 MySQL。API 只返回 `apiKeyConfigured`，前端不缓存或回显完整 Key，V12 和错误日志不保存 Key。它不是生产级 KMS。

## 14. 权限如何控制？

Spring Security 与 JWT 决定角色；studentId 只从 JWT 推导，学生 AI 资源逐次反查本人所有权；教师生成权限由 ACTIVE 三元任课关系约束；教师和管理员都不能读取学生 AI 私聊正文。

## 15. AI 生成题如何评价？

记录五项 0/1 人工质量评价、审核结果、审核时间与评论。PR #31 的状态机审核只是机器验证，论文质量统计必须来自用户真实审核，不能伪造。

## 16. 项目创新点是什么？

创新点不是“接了一个聊天接口”，而是把正式练习事实、结构化错因、当前题有限答疑、视觉上下文、可控候选生成、重复检测和人工审核接成可追溯闭环，同时保持 STANDARD 权威和 AI 可降级。

## 17. 系统局限是什么？

不做主观题 AI 自动评分、RAG、流式输出和自动发布；真实视觉曾遇到第三方 429，随后暴露的 JSON 围栏兼容已修复但没有第三次真实调用；本地 MySQL Key 保存只适合毕设演示。最终用户人工验收仍待完成。

# RIKE 答辩提纲

## 1. 研究问题

高中物化生题库系统需要同时处理确定性判分、STANDARD 解析、教学权限和大模型不确定输出。设计重点不是简单接入聊天接口，而是让 AI 能力留在可追溯、可降级、需审核的边界内。

## 2. 系统结构

系统采用 Vue 3 与 Spring Boot 4.1 前后端分离，后端保持模块化单体。MySQL 8.4 保存业务事实，Flyway V1–V29 管理 50 张业务表。自动化使用随机临时库，匿名演示使用 `rike_tiku_demo`，正式库不作为测试源。

本轮正式库内容核验为 15 个已发布专题单元、每单元 3 道题，共 45 条单元关系，学科覆盖物理 6 / 化学 5 / 生物 4；高频考点卡片共 65 张，其中 60 张来自结构化内容源。科学内容统一使用显式数学分隔符并经过 0-error 审计。学生 AI 候选先保存为本人可见 DRAFT，提交后才进入 PENDING 审核。正式 Provider 未因缺少轮换 Key 而执行，答辩时应明确说明这一边界。

最终回归为后端 215 tests、0 failures、0 errors、3 skipped，前端 68 个测试文件/220 tests 全部通过；`type-check`、`build` 和 `npm audit --omit=dev` 均通过。正式浏览器本轮因本机缺少轮换正式学生凭据记为 `BLOCKED_LOCAL_CREDENTIAL`，Demo 路由巡检不替代正式库或真人验收。这里的 skipped 只对应没有安全 Provider 凭据或平台条件的测试，不应表述为真实 Provider PASS。

## 3. 演示顺序

1. Portal 与登录，展示验证码和匿名密码恢复。
2. 学生完成一道题，查看判分、STANDARD、错题与 AI 错因。
3. 在当前题中切换模型、回答模式和联网搜索，展示安全公式渲染与来源。
4. 生成结构化变式题，作答后提交审核。
5. 教师查看候选队列，演示组卷、学生版和答案版打印。
6. 管理员查看模型诊断、密码通知和 AI 审核。

## 4. 可回答的设计问题

- 为什么 STANDARD 不能由 AI 覆盖：它是正式判分和复习依据，必须来源明确、版本固定。
- 为什么不直接发布 AI 题：候选结构校验只能发现格式问题，学科正确性仍需教师或管理员评价。
- 为什么不用微服务：本项目是单机三角色系统，模块化单体更符合部署与事务边界，未出现独立扩缩容需求。
- 为什么搜索与视觉分开配置：两者用途、endpoint 和失败语义不同，共用 Key 不等于共用 runtime usage。
- 为什么不保存思维链：学生只需要最终教学回答，保存 `reasoning_content` 会增加隐私、解释和安全风险。
- PDF 如何实现：生产页面使用 A4 print CSS 和 `window.print()`，由系统打印对话框选择打印机或另存为 PDF。

## 5. 局限

当前数据能证明代码、状态机、权限和自动化结果，不能证明真实学生的长期学习增益。外部 Provider 的可用性还受 Key、额度、限流和网络影响；无配置时系统回退到非 AI 主链。

## 6. 引用边界

答辩稿与论文只采用固定的 22 条正式参考文献白名单。项目设计阶段收集的技术调研和扩展研究资料保留在 `docs/references/research-only/`，但不进入老师审查版本。学校正式开题报告 Word 模板不在仓库中，引用内容仍需待套用学校模板。

# 面向高中物化生的 Spring Boot 大模型题库系统设计与实现

> 通用 Markdown 论文事实稿。仓库未发现学校论文 Word 模板，因此本文尚未套用学校封面、页眉页脚、目录和参考文献版式。

## 摘要

高中理科在线练习首先要保证题目、答案和解析彼此一致，然后才能根据学生的作答提供反馈。大模型可以解释错因、生成练习材料，但输出可能出现格式不稳定、事实偏移或服务不可用。本文设计并实现 RIKE 理科学习辅助系统，把高中物理、化学、生物题库、在线练习、教师教学管理和受控大模型能力放在一个前后端分离的模块化单体中。

后端使用 Java 25、Spring Boot 4.1、Spring Security、MyBatis-Plus、Flyway 和 MySQL 8.4，前端使用 Vue 3、TypeScript、Element Plus、GSAP 与 KaTeX。数据库由 Flyway V1–V29 管理，共 50 张业务表。正式判分遵循确定性规则，STANDARD 解析作为业务事实保存，AI 不能覆盖。DeepSeek 负责文本辅助，GLM 和 xAI 由管理员显式选择后用于视觉 Provider，智谱 Web Search 提供结构化网络来源。学生变式题经过 Schema V2、字段级解析、新颖度检查和确定性判分后，先保存为本人可见的 DRAFT；学生提交后才进入教师审核的 PENDING 状态，审核通过后才能进入已发布题库。

自动化测试使用随机临时 MySQL schema，匿名演示库从空库执行 Flyway V1–V29，得到 29 个成功迁移和 50 张业务表。上一轮基线为后端 210 项测试、前端 67 个测试文件/214 项测试；本轮重跑的后端专项有 39 项，学生前端专项有 30 项，均已通过。正式学生机器浏览器覆盖 4 条路线、19 项断言。由于没有轮换后的安全凭据，真实 Provider 统一记录为 `BLOCKED_EXTERNAL_PROVIDER`。这些数字只说明工程验证范围，不代表真实学生群体的教学效果。

关键词：高中理科；在线题库；Spring Boot；大语言模型；人工审核；确定性判分

## 1 绪论

### 1.1 研究背景

在线题库可以完成出题、作答和自动判分，但错题反馈常常只有固定解析。生成式人工智能为教育反馈和教学组织提供了新工具，同时带来能力边界、生态冲击和应用风险[1][3][4][6]。高中物理、化学、生物题目还要求公式、选项和分步推导排版稳定；教师需要知道题目来源、发布状态以及学生所属班级。把通用大模型直接接到答题页面，解决不了这些业务问题：生成答案可能偏离题库标准，结构化题目也可能缺选项或给出无效答案。

本项目把“确定性事实”和“生成式辅助”分开处理。题库答案、STANDARD 解析、练习快照和学生作答由业务表保存；AI 只读取授权范围内的冻结事实，输出错因解释、答疑内容或待审核候选题。该边界借鉴人机协同评价和协同教学强调的人工复核原则[9][18]，但不把相关文献的实验结果写成 RIKE 自身结论。外部服务不可用时，登录、练习、判分、错题和 STANDARD 仍可运行。

### 1.2 研究内容

本文围绕三部分展开。第一部分是三角色题库系统，包括认证、组织关系、题库、Excel 导入、练习、错题、消息和组卷。第二部分是受控 AI 链，包括模型配置、视觉上下文、结构化搜索、学生答疑和候选题审核。第三部分处理安全与验证，使用 Flyway 约束、所有权检查、Fake/Mock Provider、随机测试库和匿名 Demo 环境检查实现结果。

### 1.3 论文结构

第二章分析角色需求和非功能约束，第三章说明总体架构，第四章介绍数据库设计，第五章讨论核心功能，第六章说明 AI Provider 与受控生成，第七章分析权限和安全，第八章报告测试事实，最后讨论系统边界和后续工作。

## 2 需求分析

### 2.1 学生需求

学生需要完成三科学科练习，并在提交后获得确定性判分和 STANDARD 解析。错误题目进入错题本，同时影响掌握度统计。学生可以针对本人已提交的题目请求 AI 错因分析，或开启最多 10 轮的当前题答疑。模型、思考模式和联网搜索由管理员配置决定；学生只能选择安全选项 ID，不能指定 endpoint 或任意模型字符串。

结构化变式练习需要完整题干和可作答控件。系统支持单选、多选、填空三类自动判分题。正确答案在作答前隐藏，作答后显示 AI 解析，学生可以丢弃、换一题或提交人工审核。

### 2.2 教师需求

教师只访问本人 ACTIVE 任教关系覆盖的班级和学科。教学工作台提供学生学习统计、高频考点和消息。AI 候选题审核包括学科正确性、答案正确性、可解性、知识一致性和难度匹配等事实。教师还可以从已发布题目中筛选题目，调整题序和分值，或按题型、难度、知识点和数量执行规则组卷。

### 2.3 管理员需求

管理员维护学生、教师、班级、任课关系和题库，处理 Excel 导入、题目审核与操作日志。AI 管理页面分别配置 TEXT、VISION 和 SEARCH 用途，只返回 Key 是否已配置。登录页密码恢复使用验证码，外部响应不暴露账号是否存在；管理员处理请求时复用默认密码策略，并要求用户首次登录改密。

### 2.4 非功能约束

系统应保持模块化单体，不引入 Redis、消息队列、向量数据库和分布式事务作为运行依赖。AI 失败不能影响确定性业务。用户界面不得直接渲染模型提供的 HTML，日志不得写入 Key、Authorization、Prompt、思维链或图片 Base64。生成式 AI 教育应用还需要明确规制、素养与中小学使用边界[10][14][17]。数据库迁移必须连续执行，已经发布的 V1–V29 不再修改。

## 3 总体设计

### 3.1 系统架构

前端是 Vue 3 单页应用，通过 Axios 访问 Spring MVC JSON API。Spring Security 验证 JWT 并执行角色授权，Service 层进一步检查档案、任课和资源所有权。MySQL 保存业务事实，Flyway 是结构迁移的唯一来源。

后端按认证、教学组织、题库、练习、消息、学生 AI、AI 生成、Provider、密码恢复和试卷划分包。各包通过服务接口协作，仍在一个进程内共享事务。对于毕业设计规模的系统，这样可以少引入一层分布式复杂度，同时保留功能边界。

### 3.2 学习闭环

练习创建时冻结题干、选项、答案和解析，提交后由共享判分器处理单选、多选和填空。判分结果写入正式答题事实，错题和学习结果随后更新。AI 分析以答题事实 hash 为缓存键，不修改原题和 STANDARD。当前题答疑只加载本人会话，历史消息限制为最近 12 条且总字符不超过 6000。

### 3.3 AI 受控流程

图片题先由 GLM Vision 转换为受控视觉 JSON；文本推理和候选生成仍由 DeepSeek 完成。联网搜索使用独立 SEARCH runtime，最多返回 5 条结构化结果。视觉和网络内容在 Prompt 中明确标记为不可信上下文，不能覆盖冻结答案。

候选生成共用 Prompt、Parser、内容 hash 和质量评价表。学生场景只读取本人当前答题事实，每次生成一道题；候选先保存为本人可见的 DRAFT，显式提交后才进入 PENDING。教师和管理员场景按业务上限生成，并直接进入审核队列。

## 4 数据库设计

### 4.1 数据库演进

V1–V19 建立科目、知识点、题库、用户、组织、练习、错题、消息、日志、AI、密码恢复、试卷和学生变式。V20 增加专题类型与题目任课范围；V21 扩展知识卡片；V22 增加消息撤回与双方独立隐藏；V23 抽象 AI 会话上下文；V24 扩展难度约束；V25 保存变式新颖度元数据；V26 增加专题单元与 xAI 视觉配置；V27 增加试卷发布、冻结快照和学生提交；V28 完成卡片审核与学生状态；V29 增加知识卡片生成练习实例。

最终结构为 29 个成功迁移和 50 张业务表。纯结构快照不含 INSERT、账号、姓名或 Key，仅用于阅读；系统运行仍以 Flyway 脚本为准。

### 4.2 关键约束

密码恢复表使用生成列建立“同一账号最多一个 PENDING”的唯一约束。试卷题目同时约束同卷题目唯一、顺序唯一和分值大于 0。学生变式实例通过外键绑定学生档案、正式答题事实、母题、生成任务和候选题，状态限制为 READY、ANSWERED、SUBMITTED_FOR_REVIEW 和 DISCARDED。

题库状态机继续限制 AI 题发布。质量评价未完成时，普通题目状态转换服务拒绝将 AI 候选从 PENDING 改为 PUBLISHED。

## 5 核心功能实现

### 5.1 认证与密码恢复

登录采用用户名、密码、预期角色和一次性图形验证码。JWT 只在认证成功后返回。首次密码恢复提交只收集用户名和验证码；无论账号不存在、已停用或已有待处理请求，返回文案均相同。

管理员恢复密码时先锁定 PENDING 记录，再使用 `AdminDefaultPasswordPolicy` 生成的默认密码进行独立 BCrypt 编码。账号被标记为首次登录须改密，密码修改时间清空，请求状态与处理人同时更新。恢复或驳回写入管理操作日志，接口响应使用 no-store。

### 5.2 练习与科学内容渲染

练习服务不直接读取会变化的题库字段进行判分，而是使用练习题快照。多选答案按集合归一化，填空题按系统既有 acceptedAnswers 规则比较。该判分器也用于学生 AI 变式，防止两套规则漂移。

AI 内容由 `AiScientificContent` 解析受控 Markdown 子集，只生成 Vue 组件节点。组件支持段落、换行、有序/无序列表、粗体、行内代码、`\(...\)` 与 `\[...\]`，并谨慎归一化模型常见的美元公式分隔符。页面没有使用未过滤 `v-html`，模型输出不能注入脚本、样式或事件属性。

### 5.3 教师组卷与打印

教师先选择本人任教学科，再按关键词、题型、难度或知识点检索 PUBLISHED 题。手动模式将题目加入题篮，支持顺序调整、分值修改和移除。规则模式在数据库中筛选可自动判分题，数量不足时返回明确缺口，不调用 AI 补题。

保存时写入试卷和题目顺序、分值，计算总分并将结果冻结为 READY。学生版不返回到页面的显示逻辑中暴露答案区；答案解析版展示正确答案、STANDARD、知识点和难度。打印样式使用 A4 `@page` 和 `@media print`，按钮调用浏览器 `window.print()`。

## 6 AI Provider 与受控大模型设计

### 6.1 文本模型与思考模式

学生安全模型接口只列出 DeepSeek V4 Flash/Pro 的配置 ID、名称、模型代码、可用状态、默认状态和能力标签。Service 根据数据库 ID 再次校验用途、Provider、启用状态与 Key，不能通过请求参数改写 Base URL。

标准回答发送 `thinking.type=disabled`。深度思考发送 `thinking.type=enabled` 和 `reasoning_effort=max`，并避免发送官方在 thinking 模式下不生效的采样参数。Provider 解析最终 `content`，没有把 `reasoning_content` 放入业务 DTO、消息表或日志。

### 6.2 联网搜索

搜索 query 由学科、题干摘要、知识点和学生问题组合，长度限制为 70 字符。`OfficialWebSearchClient` 调用智谱 `/web_search`，设置结果数、超时和最多一次临时重试。解析阶段只接受公开 HTTP(S) URL，拒绝 localhost、环回、链路本地、站点本地和组播地址。

系统不抓取结果页面，也不保存整页正文。消息表只保存标题、URL、发布者和发布日期等受控来源。即使搜索摘要包含“忽略规则”等文本，Prompt 仍要求以 STANDARD 为最高业务事实。搜索失败时本轮答疑退回无来源模式。

### 6.3 学生结构化变式与审核

变式生成从本人已提交答题事实取得母题、题型、难度和知识点。候选 Parser 检查选项连续性、正确项数量、填空 acceptedAnswers 和答案结构；失败时不创建变式实例。学生生成成功后候选题本身先为 DRAFT，教师或管理员在学生显式提交后才能看到 PENDING 队列。

学生作答后，系统调用共享判分器计算结果，再显示正确答案和 AI 解析。提交审核只改变实例状态，不会直接发布题目。教师必须拥有候选所属学科的 ACTIVE 任课关系，管理员可以执行全局审核；只有审核通过，题目状态机才允许发布。

### 6.4 GLM Vision 诊断

GLM 使用 `https://open.bigmodel.cn/api/paas/v4/chat/completions` 和 `glm-4.6v-flash`。管理员连接测试采用最小匿名 PNG。Provider 把 400、401/403、429、5xx、timeout、invalid response 和 configuration error 映射为安全分类，返回 HTTP 状态、延迟和测试时间，但不返回请求、Base64、Key 或完整原始响应。

Parser 接受原始 JSON 和“整个响应只有一个 JSON 围栏”的情况；围栏外存在文字则拒绝。真实 GLM 的本轮状态必须以实际 smoke 为准，未执行时记为 NOT_RUN。

## 7 权限与安全设计

Controller 的角色规则用于粗粒度入口限制，Service 按用户档案、答题事实、任课学科和资源创建者执行细粒度授权。学生不能读取其他人的 AI 会话或变式题，教师不能组建跨科试卷，也不能访问其他教师试卷。

API Key 只保存在本地模型配置表或环境变量中，管理 API 只返回布尔字段 `apiKeyConfigured`。AI 调用日志保存安全元数据。网络来源采用 `noopener noreferrer nofollow`，服务端也再次过滤 URL。密码、JWT、Authorization 和 Provider 响应不进入论文截图。

## 8 系统测试

### 8.1 测试环境

测试环境为 Java 25.0.2、Maven 3.9.11、Node.js 24.15、npm 11.12.1 和 MySQL 8.4.10。后端集成测试动态创建 `rike_tiku_question_test_<随机后缀>`，JVM 结束时删除；正式 `rike_tiku` 不作为测试数据源。Provider 与搜索测试使用 Mock HTTP。

### 8.2 本轮已执行结果

后端最终全量为 212 项测试，0 failures、0 errors，3 项依赖真实 Provider 或平台条件的 conditional skips；本轮点名专项重跑 39 项，0 failures/errors。前端全量为 68 个测试文件、219 项测试，`vue-tsc --noEmit`、Vite build 和 `npm audit --omit=dev` 通过，audit 为 0 vulnerabilities；build 保留一个主 chunk 超过 500 kB 的警告。正式学生机器浏览器覆盖 4 条路线和 19 项断言，0 console/page/failed-request error、0 overflow。所有 Provider-dependent 结论均按 `BLOCKED_EXTERNAL_PROVIDER` 记录，不把 Mock/Fake 写成真实调用。

`rike_tiku_demo` 从空库 reset 后完整执行 V1–V29，得到 50 张业务表；seed/validate 核验 14 个匿名账号、3 个班级、4 位教师、9 名学生、9 条任课关系、66 张已审核知识卡片和 378 道题。该环境用于机器浏览器和论文截图，不包含正式人员数据或真实 Provider 凭据。

### 8.3 结果边界

上述测试可以说明状态机、约束、权限和页面逻辑按预期运行。系统没有进行真实学校班级的对照实验，也没有问卷样本，因此本文不报告学习成绩提升、满意度或 AI 准确率。当前没有可安全使用的轮换后凭据，DeepSeek variant、DeepSeek tutor、GLM Vision、xAI Vision 与 Web Search 的真实 smoke 均记录为 `BLOCKED_EXTERNAL_PROVIDER`，Mock/Fake 自动化不替代真实 Provider 结论。

## 9 结论与展望

本文实现了一个覆盖题库、练习、教学组织和受控 AI 的高中理科学习系统。系统把正式判分和 STANDARD 解析固定在业务链中，对 AI 内容做安全渲染和上下文限制，候选题在发布前经过人工审核；外部 Provider 不可用时，登录、练习、判分和错题等非 AI 功能仍可使用。Flyway 约束、随机测试库和匿名 Demo 为复验提供了条件。

取得学校授权后，可以开展真实用户测试，观察不同反馈方式对错题复习的影响。工程上还可以改进前端代码分包、试卷编辑持久化和 Provider 可观测性，但这些工作应继续保持 STANDARD 与人工审核的边界。

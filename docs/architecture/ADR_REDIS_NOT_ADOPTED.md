# ADR：当前版本不采用 Redis

- 状态：Accepted
- 日期：2026-08-12
- 适用范围：RIKE 本科毕业设计最终工程基线

## 背景

RIKE 是单机部署的前后端分离模块化单体，没有多实例分布式 Session，也没有需要跨节点共享的高吞吐实时状态。账号、练习、审核、AI 分析和生成事实均需要 MySQL 持久化；图形验证码生命周期短且当前实现有明确容量与过期控制。

## 决策

当前版本不引入 Redis，不增加 Redis 依赖、服务或 Docker 容器。MySQL 继续承担持久化；验证码和有限内存状态由单实例后端管理；视觉上下文复用使用 V14 的 MySQL 表。

## 理由

- 当前架构和答辩环境均为单实例，Redis 不能解决已存在的核心问题。
- 引入 Redis 会增加安装、配置、健康检查、数据一致性、测试矩阵和现场故障面。
- 现有数据量和并发目标下，收益不足以覆盖部署与维护成本。
- 明确不采用比“预留但未使用”更可解释，也避免把基础设施数量误当成系统创新。

## 后果与未来条件

优点是本地启动更稳定、依赖更少、测试更可重复；代价是内存验证码状态不能跨实例共享。若未来出现多实例部署、集中 CAPTCHA、短期热点缓存或分布式限流需求，可在新的容量证据和失效策略下重新评估 Redis。该未来可能性不是当前实现能力。
